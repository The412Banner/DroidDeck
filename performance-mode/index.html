What the fixes do

  1. 1

    Frames go straight back to the game

    DroidDeck app (compositor) · PR #1563

    Problem

    With no frame limit, DroidDeck's compositor still handed each finished buffer back to the game only once per screen refresh. Vulkan, OpenGL and Direct3D 12 games sat waiting for a free buffer and stalled near the refresh rate.

    Fix

    With no limit, buffers go back as soon as gamescope is done with them.

    What it saves

    Not a saving: the game is allowed to draw more. Measured with this fix alone, Vulkan went from about 250 to 948 fps and OpenGL from about 330 to 903.

  2. 2

    gamescope stops re-asking about the window

    gamescope 3.16.29-p13 (patch 0117)

    Problem

    On every frame, gamescope's Vulkan layer asked Xwayland several questions about the game window (size, flip permission, parent, children, top level) and waited for each answer.

    Fix

    The answer is reused for 100 ms (DROIDDECK_WSI_BYPASS_CHECK_MS=100).

    What it saves

    Xwayland went from 24–32 % of a CPU core to about 12 % in Vulkan, and the game thread stops waiting on it: Direct3D 11 +48 %, OpenGL +16 %, Vulkan +10 %.

  3. 3

    Wine stops asking wineserver twice per frame

    DroidDeck-Proton 11-11.6 and later (Wine bab12909)

    Problem

    Wine's X11 driver checked on every frame, twice, whether the window needs off-screen rendering, each time a round trip to wineserver. DXVK's present thread spent 65 % of its time presenting, about 86 % of that waiting on wineserver.

    Fix

    The answer is reused for 100 ms (WINE_OFFSCREEN_CHECK_MS=100).

    What it saves

    wineserver and the game's present thread are woken far less: Direct3D 9 +33 %, Direct3D 11 +26 %, Direct3D 12 +20 %, Vulkan +5 %.

  4. 4

    More frames in flight when uncapped

    DroidDeck app

    Problem

    With the first three fixes in, the game's present thread spent 70 % of its time waiting for gamescope to hand a buffer back.

    Fix

    At least 8 swapchain images when no limit is set (GAMESCOPE_WSI_MIN_IMAGE_COUNT=8); with Steam's Frame Limit on, gamescope keeps its default 3 so a limited game doesn't queue frames ahead (patch 0119, PR #1650).

    What it saves

    Vulkan 1,096 → 1,844 fps, OpenGL 1,066 → 2,447, Direct3D 12 1,266 → 3,954.

  5. 5

    gamescope stops re-finding the game window and wakes up on time

    gamescope 3.16.29-p17 (patches 0121, 0122) · PR #1672

    Problem

    On every frame gamescope walked Xwayland's window tree to find the game's top window, and DroidDeck's "frame shown" and "buffer free" messages could wait up to one refresh before gamescope read them.

    Fix

    0121 reuses the window for the same swapchain for 100 ms. 0122, an upstream gamescope fix by Matthew Schwartz, wakes gamescope as soon as those messages arrive.

    What it saves

    Vulkan +9 % fps and 1 % lows 704 → 1,032 (39 → 51 at a 60 fps limit); Xwayland in Direct3D 11 31.7 % → 6.1 % of a core, gamescope's Wayland thread 37.4 % → 17.9 %.

  6. 6

    The screen tick gets its own thread

    DroidDeck app · PR #1678

    Problem

    The compositor's once-per-refresh tick ran on the app's busy UI thread: 8 to 13 ticks every 10 s came more than 2 ms late, the worst 7–13 ms.

    Fix

    The tick runs on its own display-priority thread.

    What it saves

    0 to 1 late ticks per 10 s, the worst 2.5–5 ms. Frame rate unchanged; a steadier screen.

  7. 7

    Windows CPU 0 is the fastest core

    DroidDeck app · PR #1697

    Problem

    Wine numbered the Windows CPUs like the phone's, so CPU 0 was core 0, a small core with about a third of the fast core's power. GTA IV and other games that pin their main thread to CPU 0 ran it there.

    Fix

    Windows sees the game's cores fastest first, read from each core's own rating. Cores picked for a game and Proton's own per-game core limits still apply.

    What it saves

    GTA IV 32.1 → 61.1 fps. Games that don't pin threads, like DiRT Showdown and AIO, are unchanged.

Fixes 1–4: gains measured on 2026-10-25 as each was added on top of the previous ones. Fixes 5–7: measured on 2026-10-27, each against the build without it. Related per-game options under a game's settings: the WineD3D Vulkan renderer for DirectDraw and Direct3D 1–7 games (AIO D3D7 74 → 950–1,080 fps) and DXVK for Direct3D 8 (PROTON_DXVK_D3D8, AIO D3D8 2,408 → 3,097 fps).
