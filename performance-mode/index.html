Performance mode, off and on

One switch under Mode settings > Frame rate. It stops DroidDeck, gamescope and Wine from waiting on each other every frame, and with a frame limit set, it stops games drawing frames the screen never shows.

What the switch fixes

  1. 1

    Frames go straight back to the game

    DroidDeck app (compositor)

    Problem

    With no frame limit, DroidDeck's compositor still handed each finished buffer back to the game only once per screen refresh. Vulkan, OpenGL and Direct3D 12 games sat waiting for a free buffer and stalled near the refresh rate.

    Fix

    With Performance mode on and no limit, buffers go back as soon as gamescope is done with them.

    What it saves

    Not a saving: the game is allowed to draw more. Measured with this fix alone, Vulkan went from about 250 to 948 fps and OpenGL from about 330 to 903. It costs power, so it only applies with no limit.

  2. 2

    gamescope stops re-asking about the window

    gamescope 3.16.29-p13 (patch 0117)

    Problem

    On every frame, gamescope's Vulkan layer asked Xwayland several questions about the game window (size, flip permission, parent, children, top level) and waited for each answer.

    Fix

    The answer is reused for 100 ms (DROIDDECK_WSI_BYPASS_CHECK_MS=100).

    What it saves

    Xwayland went from 24–32 % of a CPU core to about 12 % in Vulkan, and the game thread stops waiting on it: Direct3D 11 +48 %, OpenGL +16 %, Vulkan +10 %.

  3. 3

    Wine stops asking wineserver twice per frame

    DroidDeck-Proton 11-11.6 and later (Wine bab12909)

    Problem

    Wine's X11 driver checked on every frame, twice, whether the window needs off-screen rendering, each time a round trip to wineserver. DXVK's present thread spent 65 % of its time presenting, about 86 % of that waiting on wineserver.

    Fix

    The answer is reused for 100 ms (WINE_OFFSCREEN_CHECK_MS=100).

    What it saves

    wineserver and the game's present thread are woken far less: Direct3D 9 +33 %, Direct3D 11 +26 %, Direct3D 12 +20 %, Vulkan +5 %.

  4. 4

    More frames in flight when uncapped

    DroidDeck app

    Problem

    With the first three fixes in, the game's present thread spent 70 % of its time waiting for gamescope to hand a buffer back.

    Fix

    At least 8 swapchain images when no limit is set (GAMESCOPE_WSI_MIN_IMAGE_COUNT=8). Mailbox mode, so no added latency; about 3.7 MB of memory per image at 720p.

    What it saves

    Vulkan 1,096 → 1,844 fps, OpenGL 1,066 → 2,447, Direct3D 12 1,266 → 3,954.

  5. 5

    A frame limit holds the game, not just the screen

    New · branch fix/frame-limit, not merged

    Problem

    A limit only paced what reached the screen. A game without vsync kept drawing hundreds of frames that were thrown away: AIO at a 60 fps limit drew 155 to 2,446 fps. gamescope's own --framerate-limit option is reset on its first frame (gamescope 3.16.29), so the option alone does not hold games.

    Fix

    With Performance mode on, the session sets the per-game limit over gamescope's control channel and sets it again whenever Steam resets it (Steam does once while it starts); gamescope's limiter then makes the game wait for its turn.

    What it saves

    At a 60 fps limit (three runs each, same build): the game draws 60.0 fps instead of 945; whole-device power 9.4 → 7.1 W, busy cores 2.6 → 1.3 of 8, GPU 11 → 5 % busy.

The per-fix gains were measured on 2026-10-25 as each fix was added on top of the previous ones. Related per-game options under a game's settings, not part of the switch: the WineD3D Vulkan renderer for DirectDraw and Direct3D 1–7 games (AIO D3D7 74 → 950–1,080 fps) and DXVK for Direct3D 8 (PROTON_DXVK_D3D8, AIO D3D8 2,408 → 3,097 fps).
